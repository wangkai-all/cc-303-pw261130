# RiskLab · 贷款样本与回测工具（虚构数据）

一个**从零实现的纯本地**演示工具：用确定性合成数据构造申请/审批/放款/还款/逾期/更正事件，按申请批次留出或按日滚动做时点回测，比较两版透明评分规则，并提供一个可交互网页查看准备情况、样本入选原因、分层结果和版本差异。

> ⚠️ 所有客户、金额、还款与逾期都是程序合成的虚构数据。页面中的所有评分、通过率、坏账率只用于演示时点口径与回测流程，**不构成任何真实授信建议**。

## 快速开始

环境要求：Python 3.11+（仅标准库，无第三方依赖）。

```bash
# 1. 写入虚构原始数据 + 三版规则（v3 为未启用候选）
python3 -m risklab.cli init --seed

# 2. 可选：一次生成两种回测方式 × 两版规则的演示报告并发布一份
python3 -m risklab.cli demo --seed

# 3. 启动网页
python3 -m risklab.cli serve --port 8765
# 打开 http://127.0.0.1:8765
```

网页中的四步流水线按钮就是下面四条命令：样本构建 → 标签回补 → 回测 → 发布。它们各自建任务、写审计、可中断恢复。

```bash
python3 -m risklab.cli sample   --cutoff 2026-06-30 --mode batch_holdout
python3 -m risklab.cli labels   --sample SMP-xxxxxxxxxxxx --as-of 2026-09-30
python3 -m risklab.cli backtest --sample SMP-xxxxxxxxxxxx --labels LBL-xxxxxxxxxxxx \
                                --policy policy-base-v1 --mode batch_holdout
python3 -m risklab.cli publish  --report RPT-xxxxxxxxxx
```

测试与界面冒烟检查：

```bash
python3 -m unittest discover -s tests -v
# 需要 Node 时：node tests/ui_smoke.js（先启动 serve）
```

## 数据与时间口径

每个业务事件同时带两个日期：

| 字段 | 含义 |
| --- | --- |
| `occurred_on` / 申请日 | 业务真实发生日 |
| `recorded_on` / 入库日 | 该记录在数据仓库中可见的日期 |

这是整个工具的支点：**特征只能看到“决策日之前已经入库且已经发生”的信息**。合成数据刻意制造了三类陷阱：

1. 审批结果、放款、还款、逾期都有批处理延迟，部分记录跨日入库；
2. 约 5% 的申请主档在审批之后才入库 → 这类申请直接排除（`feature_late`）；
3. 贷后更正事件的业务日可能早于审批日，但入库晚于审批日 → 不能进入审批时特征，只作为“被隔离记录”计数；
   历史申请的主档也必须已入库，才会被计入 `prior_loans`。

数据快照日为 2026-09-30：快照之后发生/入库的事件不在本地库中，形成真实的右删失边界。

## 关键设计

### 1. 时点隔离（point-in-time）

`risklab/engine.py::build_sample` 先按 `applied_at <= cutoff AND recorded_on <= cutoff` 取申请与事件，再对每笔客户计算历史特征时逐一加上 `recorded_on <= decision_on` 约束。样本行里保存 `visibility` 证据：决策日、可见规则、被隔离的晚到记录及示例。网页“样本追溯”逐条展示可见/隔离状态。

### 2. 标签成熟度

- 观察窗：放款日起 6 个月；
- 坏账：窗口内任一周期的 DPD ≥ 30，确认日取该事件**入库日**（早发生但晚补录不能提前算坏）；
- 好客户：观察窗结束 **+ 30 天结算缓冲** 之后才允许记为 good；
- 其余一律 `censored`（删失），**绝不当成好客户**。所有坏账率分母都只包含 good+bad。

`_maturity()` 在截止日到快照日之间多个时点重算“可用样本数/覆盖/坏账率”，网页以曲线展示：等得越久样本越全，时效越差。

### 3. 两种回测方式与取舍

| 方式 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| 按申请批次留出 `batch_holdout` | 只把成熟率 ≥90% 的最近 2 个申请月作为留出集，其余月份作为参考集 | 留出边界清晰、同批客户环境一致，适合版本验收 | 截止日附近批次尚未成熟，必须整体推迟；报告时效落后 |
| 按日滚动 `daily_rolling` | 最近 6 个申请月逐月评估，之前的月份作为历史参考 | 每月重估，能较快反映近期变化 | 越近的窗口成熟率越低，各窗口口径不一致 |

报告同时输出被推迟的月份及各自成熟率，而不是“用最新但未成熟的数据凑数”。若截止日前没有任何成熟批次，报告标记 `windows.degraded` 并说明原因，不生成虚假留出集。

### 4. 分开执行、可恢复、不混版

- **样本**：配置 + 行内容一起做 SHA-256 封存（`sealed_hash`）；同一配置幂等复用。
- **标签**：样本 ID + 标签配置 + as_of 生成独立 `label_batch_id` 并封存全部标签。
- **回测**：先重算样本与标签封存摘要，再校验规则定义摘要，三者任一不符即拒绝出报告；样本模式与回测模式必须一致。
- **发布**：再次校验报告清单、样本/标签/规则摘要，通过后状态变为 `published`；同截止日同模式同规则的旧发布版会被标记 `superseded`，其他规则版本的发布不受影响。
- 每份报告记录 `sample_run_id`、`label_batch_id`、`policy_id` 与三个摘要，标签换版不会回写历史报告。
- 任务写入 `runs` 表并逐步记录；中断后点“继续此任务”会重新执行，但已封存的样本/标签会被复用，因此不会出现半成品或同一报告混用两版标签。

### 5. 基础评分规则

`risklab/policy.py` 是透明加权分箱（收入带、征信、就业年限、存量负债、期限），输出 300–850 分与阈值结论，并给出逐项拆解。两版规则仅在权重与阈值上不同，网页可并排比较；不训练复杂模型。

## 网页功能

- 选择截止日、回测方式、规则版本；
- 四步流水线按钮、模拟中断与断点恢复；
- 成熟度曲线、样本/标签/规则封存校验状态；
- 分层结果（评分带、收入带、征信、渠道、产品、申请月），未成熟样本单列；
- 异常与隔离：各排除原因占比、晚到记录示例；
- 样本追溯：输入申请号或客户号，查看入选原因、可见/隔离事件时间线、标签观察窗、评分拆解；
- 版本对比：默认选同一样本同一截止日的另一版规则；若样本/标签/模式不一致会明确警告。

## 目录结构

```
risklab/
  synth.py      确定性虚构数据生成（含入库延迟、贷后更正、右删失）
  store.py      SQLite 存储：原始表、封存样本、标签批次、报告、任务、审计
  policy.py     透明基础评分规则与版本
  engine.py     样本构建、时点特征、标签回补
  reporting.py  窗口划分、指标、成熟度、完整性校验、发布与对比
  webapp.py     标准库 HTTP API + 静态页面
  cli.py        命令行入口
web/            无构建步骤的原生 HTML/CSS/JS 前端
tests/          unittest 端到端测试 + jsdom 界面冒烟脚本
var/            本地数据库与报告工件（已被 .gitignore 忽略）
```

## 已知边界（有意为之）

- 评分规则是演示用分箱，不做训练/调参，AUC/KS 仅用于验证分层方向；
- “按日滚动”以月为评估步长，展示滚动口径而非逐日重训；
- 合成数据的违约过程是简化模型，指标数值本身没有业务含义；
- 本地单机、无鉴权，仅用于离线演示。
